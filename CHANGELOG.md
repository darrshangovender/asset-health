# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [0.1.1] - 2026-10-14

Fixes for an adversarial review of 0.1.0 (17 findings). Every README number was regenerated by
`python benchmarks/run.py`; the headline moved, mostly towards the system looking less special.

### Added
- **Severity sweep** in the benchmark: the held-out seeds are rebuilt with every injected failure
  signature scaled by 0.5, 0.3 and 0.15 (`SimConfig.degradation_scale`), nothing re-tuned, and the
  system is scored against both fixed limits at each scale. The README leads with this curve and
  states where the system stops beating the limits.
- **Component ages and wear-out lives.** Each asset class has an illustrative Weibull life
  (`AssetTypeProfile.life_weibull`, shape > 1); each component's age at the start of the record is
  drawn consistently with when (or whether) it fails, from a separate random stream so the
  simulated signals are unchanged. `AssetSpec.component_age_days` carries it.
- A second fixed-limit baseline on **temperature rise above ambient**, reported alongside the raw
  one; both tune `k` per channel.
- Export-structure checks in the data-quality gate, all of which **block** the asset: rows out of
  time order (a cleanly newest-first file is reversed and flagged instead), two collectors
  interleaved, a sampling cadence that differs from the configured one, and a re-timed grid that
  would run past the last real timestamp. Opt-in `IngestConfig(resample=True)` / CLI `--resample`
  averages a finer cadence onto the grid.
- Erratic-vibration-sensor check (loose mount, cable fault): masks every vibration channel while
  the hour-to-hour roughness of overall vibration is far above the asset's normal.
- `as_of` on `ingest_asset`, `run_asset` and `run_source`; `report_as_of` recomputes the
  data-quality verdict from the causal masks up to an instant.
- Results: RUL at decision time, coincidental alarms, when the system acted, diagnosis on the
  multi-family asset types, per-class renewal-failure probabilities.

### Changed
- **Calendar baseline is age-based and can now win.** It replaces a part when its age reaches a
  tuned fraction of the class's characteristic life, and any replacement before the failure
  prevents it (0.1.0 credited only replacements inside `[onset, failure)` under a memoryless failure
  process, so the baseline could not beat run-to-failure by construction).
- **Event scoring:** an alert that opened inside a failure window before the degradation reached 5%
  latent severity is a (coincidental) false alarm, not a detection.
- The fixed limits' false-alarm rate uses the hours each limit was itself watching.
- **RUL headline is scored at decision time** (checkpoints up to the planned replacement); the
  pooled all-checkpoint figure is reported alongside.
- Baseline tuning uses the same 1% plateau rule as the system's tuning.
- Every timestamp entering the package (telemetry, maintenance records, `--as-of`) is converted to
  naive UTC; tz-aware CMMS records no longer crash `run_asset`, and offsets that change at daylight
  saving are accepted.
- `--as-of` reads nothing after the instant anywhere, including the asset-block decision and the
  work order's data-quality note. `analyse_runs` refuses to replay a moment from a run that was
  blocked by later data.
- The narrative guardrail also rejects wrong or out-of-vocabulary fault names (including
  paraphrases), spelled-out quantities, numbers bound to the wrong RUL quantile, written-out dates
  not in the order, severity words above the order's severity and escalation language below
  CRITICAL; year, month and day of a date are no longer free numbers.
- The artefact and tuning caches hash the source of the modules they depend on.
- README: severity curve first; baselines described as statistical limits and age-based
  replacement; RUL interval called conservative, not calibrated; the inert cost exponent and
  latest-safe-date stated plainly; Limitations extended (physics, monitoring practice, data-quality
  coverage, cost model).

## [0.1.0] - 2026-10-14

### Added
- Seeded, physically motivated SYNTHETIC fleet simulator: operating regimes (load, speed, ambient),
  order-domain vibration spectra with bearing defect lines derived from geometry (BPFO, BPFI,
  FTF, BSF), temperature, current, power, pressure and flow, and injected degradation for four
  failure modes (bearing spall, impeller wear, liner wear, overheating) with ground-truth
  timestamps. Historian-style data faults: dropouts, stuck sensors, sentinel codes, spikes,
  communication outages, duplicate rows and logger clock drift.
- Data-quality gate (`ingest`) with explicit pass/warn/fail outcomes and a per-asset report.
  Masked values never reach a detector.
- Regime-normalised residual features, per-asset healthy baselines learned on a commissioning
  window, trend slopes.
- Detection: CUSUM and Isolation Forest fused with an explainable rule layer that names a fault
  hypothesis and the evidence behind it.
- Remaining useful life with an uncertainty interval: health-index trend extrapolation (Theil-Sen)
  plus linear quantile regression, conformally widened on calibration seeds.
- Cost-aware alert policy with debounce and hysteresis, severity levels, structured work-order
  recommendations, and an optional LLM narrative behind a Protocol with a citation guardrail and a
  deterministic template fallback.
- Event-level evaluation on held-out seeds (detection rate per failure mode, lead time,
  false alarms per asset-month, RUL error and interval coverage, policy cost against fixed-threshold
  and calendar baselines, ablations), with train, calibration and evaluation seeds kept disjoint.
- CLI (`asset-health simulate|check|detect|rul|report`, with `--as-of` to replay a past moment using
  nothing later), self-contained HTML report, CSV and Parquet adapters, multi-stage Dockerfile and
  docker-compose (not yet built by the author).
